3. Mobject — the base object
File
manimlib/mobject/mobject.py
What it is
Mobject means:
the base visible object in Manim
It is the broadest visual object abstraction.
What it gives
At this level, you get general object behavior such as:
position / transformation
grouping
copying
adding children / submobjects
moving / scaling / rotating
updater support
So Mobject is not yet specifically “a vector path”. It is the general concept of “something that can appear in a scene.”
Mental model
Think:
Mobject = general visual thing

4. VMobject — vectorized object
File
manimlib/mobject/types/vectorized_mobject.py
What it is
VMobject means:
vectorized mobject
This is the class for path-based geometric objects.
What it adds beyond Mobject
At this level, Manim introduces vector-shape styling and geometry concepts like:
stroke
fill
path points
outline drawing
partial path rendering
This is why shapes like:
Line
Circle
Polygon
Arc
belong conceptually here.
Mental model
Think:
VMobject = Mobject + vector path geometry

5. SVGMobject — SVG imported as vector object
File
manimlib/mobject/svg/svg_mobject.py
What it is
SVGMobject means:
load SVG and convert it into vector geometry
Your notes summarize this very directly:
SVGMobject converts SVG to vector geometry
parses paths into points
What it adds
It takes SVG path data and turns it into Manim vector objects.
So instead of manually coding points for every letter/shape, it can import SVG-defined paths and transform them into internal vector point structures.
Mental model
Think:
SVGMobject = VMobject created from SVG path data

6. StringMobject — text string mapped to geometry
File
manimlib/mobject/svg/string_mobject.py
What it is
This is the bridge between:
original text string meaning
geometric/vector representation
Your notes say:
StringMobject keeps mapping between text string ↔ geometry
handles substring selection
Why needed
If text becomes pure geometry, the system would otherwise lose the connection between:
characters / words / substrings
the shapes on screen
But Manim wants to do things like:
color specific letters
animate subsets of text
select words
So StringMobject helps preserve that relationship.
Mental model
Think:
StringMobject = SVG/vector text + mapping back to string structure

7. MarkupText and Text
File
manimlib/mobject/svg/text_mobject.py
Text
This is the user-facing object you write:
txt = Text("Hello")
Your notes describe Text as:
regular text
used for titles, labels, headings
based on Pango-style text rendering
What happens internally
Your notes give the internal text pipeline:
"mylinehub"
   ↓
MarkupText
   ↓
Pango (via manimpango)
   ↓
SVG file (temporary)
   ↓
SVGMobject parses it
   ↓
VMobject (points)
and explicitly say:
Text() is not text it becomes vector paths.
So by the time Text is rendered/animated, it is stored as geometry, not as “live editable text” like in a word processor.
Mental model
Think:
Text = user-friendly text API on top of vector path machinery

8. Tex is different from Text
File family
Text-like but different rendering path.
Your notes distinguish them clearly:
Text("slope") for words
Tex("m = ...") for formulas
Difference
Text uses Pango / font text pipeline
Tex uses LaTeX rendering pipeline
But both end up as geometry that Manim can animate.
So:
Text  → normal font text → vector geometry
Tex   → LaTeX formula    → vector geometry

9. ImageMobject is different from all of the above
File family
Image-related object, not SVG/vector path family.
Your notes say:
ImageMobject is for PNG/JPG/GIF raster images
SVGMobject is for vector images
Meaning
This is important:
ImageMobject = pixels
SVGMobject / Text / Tex = vector/path-based geometry
So if you want:
crisp scalable paths
outline drawing
mathematical path animation
vector objects are far more suitable.

10. Style/config levels — why config rules differ
This was one of your main confusions. Here is the clean model.
Config levels from your YAML snippet
You showed blocks like:
scene:
vmobject:
mobject:
tex:
These are different levels of the framework.

A. mobject: level
Broad default settings for base visual objects.
Examples:
default_mobject_color
default_light_color
These are generic defaults.
B. vmobject: level
More specific defaults for vector/path objects.
Examples:
default_stroke_width
default_stroke_color
default_fill_color
These only make sense for vectorized shapes.
That is why stroke/fill live here, not in base Mobject.

C. scene: level
Runtime scene behavior.
Examples:
show_animation_progress
leave_progress_bars
preview_while_skipping
default_wait_time
These are not shape styles. They are scene execution defaults.

D. tex: level
Defaults specific to the TeX rendering system.
Examples:
template
font-size calibration

11. Style inheritance / specificity diagram
This is the clean way to think about style resolution:
General base defaults
   ↓
Mobject defaults
   ↓
VMobject defaults
   ↓
Specific subclass behavior
   ↓
Explicit styling in your code
So for a vector object like Line:
Mobject default color
   ↓
VMobject stroke/fill defaults
   ↓
Line-specific behavior
   ↓
your explicit set_stroke / set_color / set_fill
This is why default_mobject_color and default_stroke_color are not the same thing.
one is broad fallback
one is specific vector outline styling

13. Animation objects — another important “object type”
Animation is a parallel object system.
Important files:
manimlib/animation/animation.py
manimlib/animation/creation.py
manimlib/animation/transform.py
manimlib/animation/fading.py
Your notes already singled these out as the key animation files to study.
Core animation meanings
From your notes:
ShowCreation = draw outline/path gradually
Write = reveal text/formula as if written
FadeIn / FadeOut = softly appear/disappear
Transform = morph one object into another
LaggedStart = stagger multiple animations
So animation objects are not visible shapes themselves. They are objects describing how visible objects change over time.

15. Text into vector — full intuitive flow
Here is the complete picture again:
Python string
   ↓
Text(...)
   ↓
font shaping (Pango / ManimPango)
   ↓
glyph outlines
   ↓
temporary SVG/path representation
   ↓
SVGMobject parsing
   ↓
VMobject points / vector geometry
That is why:
Text can be animated with Write
text can be grouped, transformed, colored in parts
it behaves like geometry
Your notes also mention that because text becomes geometry, Manim builds mappings so you can still select words, color parts, and animate subsets.
