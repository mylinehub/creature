1. What this project is
This project is for building a reusable animated MYLINEHUB mascot:
capital M body
eyes
hat
nose
mouth
hands
legs
later pointer/stick
later teaching / walking / reacting / explaining maths
It is not just one animation.It is a character framework.
So from day 1, we design it like a proper reusable system.

2. Main project goals
We need this project to support 4 things:
A. Character creation
Build the mascot itself.
B. Character control
Control face, pose, limbs, movement.
C. Scene building
Put mascot into scenes.
D. Learning Manim properly
Use this project to understand:
grouping
transforms
anchors
coordinate space
movement
reusable animation design

3. Design principles
These are very important. I will follow these throughout.
Principle 1: Small files
No giant file unless absolutely needed.
Principle 2: One file = one responsibility
Example:
hat logic in hat file
face logic in face file
walk action in walk/actions file
Principle 3: Reusable parts
Character should be buildable once, usable everywhere.
Principle 4: Clear naming
You should be able to read structure and understand what each file is for.
Principle 5: Test scenes first
Before making final polished scenes, first make small test scenes.
That avoids confusion.

5. Why this structure is good
This is not random splitting.Each folder has a clear purpose.
config/
Only constants and design values.
Examples:
colors
default scale
eye size
hat size
animation durations
No heavy character logic here.

core/
Reusable mathematical helpers.
This is where we keep utility logic like:
point helpers
anchor helpers
motion helpers
spacing helpers
This prevents duplication.

creature/
The heart of the mascot.
This is split into 4 layers:
parts/
Raw body parts.
rigs/
How body parts move or attach.
poses/
Static named body arrangements.
actions/
Actual animations and movements.
That separation is very important.

props/
Anything the character uses or points at.
Example:
stick
board
axis plane
formula card
These are not part of the body, so they stay separate.

scenes/
Only scene composition.
Scene files should never become storage for body-construction logic.
That logic belongs in creature/.

docs/
This is useful because you are learning.We can keep learning notes and architecture notes there.

6. Development order
We should not create all files immediately.We create them in the right order.
Phase 1 — foundation
Create base project and config/core helpers.
Phase 2 — creature body
Make static M character with body + face + hat.
Phase 3 — limbs
Add arms, hands, legs, feet.
Phase 4 — rigs and poses
Make named poses and attach motion points.
Phase 5 — actions
Blink, look, wave, point, hop, walk.
Phase 6 — scene composition
Use the mascot in test and intro scenes.

9. Keep file sizes small
You said file sizes should stay small.Correct.
My recommendation:
ideal file length
40 to 120 lines for most files
150 lines max if truly needed
avoid 300+ line files unless it is a high-level scene/demo file
how to keep files small
one class or one concern per file
helper functions moved to core/
avoid storing many poses in one big file
avoid mixing construction and animation logic
This is exactly why we split into:
parts
rigs
poses
actions

10. What types of functions we will use
You asked about “types of function”.
These are the kinds we will write.
A. Constructor/build functions
Create shapes.
Examples:
build_body_m()
build_hat()
build_eyes()

B. Anchor functions
Return important points.
Examples:
get_face_center()
get_left_hand_anchor()

C. Arrange/alignment functions
Place one part relative to another.
Examples:
place_hat_above_body()
place_eyes_on_face_line()

D. Pose functions
Set static body arrangement.
Examples:
apply_neutral_pose()
apply_teacher_pose()

E. Animation/action functions
Do movement over time.
Examples:
blink()
wave()
point_to_object()

F. Scene composition functions
Used inside scene files to present objects and actions.
Examples:
introduce_creature()
show_formula_and_point()
